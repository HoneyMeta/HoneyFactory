# 交付包点表格式 v1

蜂元虚拟工厂的"标准交付包"（`GET /api/p/<工厂>/delivery.zip`）和蜂元智能 MES 的接入规范用同一份格式。
它模拟系统集成商调完现场后交给 MES 的东西：设备清单、点表、平面布置图、三维模型、接入说明。

## 1. 交付包内容

| 文件 | 内容 |
|---|---|
| `README.md` | 协议端点和命名空间、MQTT 主题与载荷、Modbus 从站/寄存器约定、坐标系、动作级信号 |
| `points.xlsx` | 四张表：**设备**、**点表**、**协议**、**说明** |
| `layout.dxf` | 平面布置图（DXF R12 ASCII，单位米），每类一层，设备是带属性的块 |
| `models/<设备类型>.glb` | 每类设备一个三维模型（glTF 2.0 二进制，米，Y 向上） |
| `models/scene.glb` | 整厂场景：每台设备一个节点，节点名 = 设备编码 |

接口：

- `GET /api/p/<工厂>/delivery.zip?protocols=primary|all`：服务端生成（三维是简化模型）。
- `POST /api/p/<工厂>/delivery.zip`，body `{"models": {"<类型>": "<GLB base64>"}, "scene": "<GLB base64>", "protocols": "primary"}`：网页按钮用这个，三维模型来自界面（three.js GLTFExporter）。
- `GET /api/p/<工厂>/delivery/points.xlsx | layout.dxf | README.md | models/<类型>.glb`：单个文件。
- `GET /api/p/<工厂>/delivery/info`：设备数、点数、各协议点数、有动作信号的设备。

## 2. 设备表（工作表"设备"）

列顺序固定，表头就是下面的列名（中文，含括号里的单位）。

| 列 | 类型 | 说明 |
|---|---|---|
| 设备编码 | 文本，必填，唯一 | 和点表的"设备编码"、DXF 块属性 `CODE`、三维节点名一致 |
| 设备名称 | 文本 | |
| 设备类型 | 文本 | 如 加工中心、造型线、中频炉、立体仓库 |
| 型号 | 文本 | |
| 厂家 | 文本 | |
| 车间 | 文本 | 组织结构第一层 |
| 产线 | 文本 | 组织结构第二层（虚拟工厂里是区域） |
| 工位 | 文本 | 组织结构第三层（`WS-<设备编码>`） |
| X(m) | 数字 | 设备中心，工厂坐标（见第 5 节） |
| Y(m) | 数字 | 设备中心，工厂坐标 |
| 宽(m) | 数字 | 沿设备自身 X 方向的外形尺寸 |
| 深(m) | 数字 | 沿设备自身 Y 方向的外形尺寸 |
| 朝向(°) | 数字 | 绕竖直轴，逆时针为正，0–360；和 DXF 块插入角一致 |
| 3D模型文件 | 文本 | 交付包里的相对路径，如 `models/cnc.glb` |
| 理想节拍(s) | 数字，可空 | 设计循环时间，算性能开动率用 |
| 备注 | 文本 | |

## 3. 点表（工作表"点表"）

一行 = 一个采集点（一种协议的一个地址）。`protocols=primary`（默认）时每个点一行，用设备的主协议（看网络线：opcua → OPC UA，modbus_tcp → Modbus，其它经网关上 MQTT；没有该协议地址时依次退到 MQTT / OPC UA / Modbus）；`protocols=all` 时每种协议各一行，点位编码后面加 `@<协议>`。

| 列 | 取值 | 说明 |
|---|---|---|
| 点位编码 | 文本，必填，唯一 | 整理过的现场：`<设备编码>.<点位路径用 . 连接>`，如 `CNC1.Monitoring.Spindle.Load`；原始现场：PLC 符号名，如 `PLC2.DB10.DBD4`、`M3_ZZFZ`、`U11.HR1000` |
| 设备编码 | 文本 | 属于哪台设备（设备表里的编码） |
| 含义 | 文本 | 中文含义 |
| 单位 | 文本 | 工程单位（%、°C、kW、kWh、s、件…） |
| 数据类型 | `bool` / `int` / `float` / `string` | 工程值的类型 |
| 读写 | `R` / `RW` | RW = 设定值，可写 |
| 用途 | `state` / `alarm` / `count` / `power` / `energy` / `load` / `temp` / `quality` / `action` / `step` / `param` / `other` | 见下表 |
| 协议 | `opcua` / `mqtt` / `modbus` | |
| 地址 | 文本，必填 | OPC UA：完整 NodeId，如 `ns=2;s=foundry-housing/CNC1/Monitoring/Spindle/Load`；MQTT：完整主题；Modbus：`从站:表:地址`，表是 `hr`（保持寄存器）或 `coil`（线圈），地址从 0 起（PDU 地址），如 `11:hr:1000` |
| 缩放 | 数字，默认 1 | 工程值 = 原始值 × 缩放 + 偏移 |
| 偏移 | 数字，默认 0 | |
| 采集周期(ms) | 整数 | 建议采集周期；`0` = 变化即推送（MQTT） |
| 报警下限 | 数字，可空 | |
| 报警上限 | 数字，可空 | |
| 正常范围 | 文本，可空 | 如 `0~85` |
| 备注 | 文本 | Modbus 多寄存器的编码和字序（如 `float32 ABCD，2 个寄存器`）、状态码对照等 |

用途：

| 用途 | 含义 | 例子 |
|---|---|---|
| state | 运行状态 | Common/State（Idle / Executing / Starved / Blocked / Stopped / Setup / Planned；Modbus 是 int16 状态码 0–6） |
| alarm | 报警 | Common/Alarm（文字；Modbus 是线圈，有报警 = 1） |
| count | 计数 | 产量、合格数、循环计数 |
| power / energy | 功率 kW / 电能 kWh | Common/PowerKW、Common/EnergyKWh |
| load | 负载 / 电流 | 主轴负载 |
| temp | 温度 | |
| quality | 质量 / 检测结果 | 缸孔直径、检测结论 |
| action | 动作信号 | 电磁阀、到位传感器、循环进行中、上次动作用时 |
| step | 程序段号 | NC 程序段、机器人程序步 |
| param | 设定参数（可写） | 倍率、节拍设定 |
| other | 其它 | |

### 原始现场

原始现场（集成商刚调完、还没整理）的点表只填 **点位编码 / 协议 / 地址 / 数据类型** 四列，其余空着。接入方按地址读值、看变化，结合设备表和图纸补全含义、单位、设备、用途。

## 4. 协议表和说明表

- "协议"表：`协议 | 项目 | 值 | 说明`，列出 OPC UA 端点和命名空间、NodeId 规则、MQTT Broker、主题规则、载荷格式、写入与回执、Modbus 端点、地址约定、数据类型和字序、对外时间。
- "说明"表：`表 | 列 | 说明`，本文第 2、3 节的内容，外加交付包格式版本、工厂、生成时间、现场状态（已整理 / 原始现场）。

## 5. 坐标系、图纸和三维

- 工厂坐标：原点在厂房左下角，X 向右，Y 向上，单位米。
- DXF：和工厂坐标一致（`$INSUNITS = 6`）。图层：`VF_WALL` 墙体、`VF_AREA` 区域、`VF_AISLE` 通道、`VF_DEVICE` 设备、`VF_CONVEYOR` 输送线、`VF_AGV_PATH` AGV 路径与站点、`VF_TEXT` 文字。
  每台设备一个块 `DEV_<编码>`（外形矩形 + 指向设备自身 +X 的短线），插入点 = 设备中心，插入角 = 朝向；属性 `CODE`（可见）、`NAME`、`TYPE`。非 ASCII 字符写成 `\U+XXXX`。
- glTF：Y 向上；glTF X = 工厂 X，glTF Y = 高度，glTF Z = −工厂 Y；朝向 a 对应绕 +Y 转 a。场景节点 `extras` 里有 `code`、`name`、`type`、`model_file`。

## 6. 动作级信号（节拍分析）

加工中心、造型线、机器人单元（以及参数 `actions` 打开的通用加工块）在 `Actions/` 下有循环内的动作信号：
电磁阀 / 指令（`…Valve`、`…Cmd`）、到位传感器（`…Extended` / `…Retracted` / `…Closed` / `…Opened`）、`SpindleRun`、`ProgramStep`、`CycleOn`（上升沿 = 循环启动，下降沿 = 循环结束）、`CycleCount`，
以及 `Actions/Last/<动作>` 上次动作用时（秒）、`Actions/Last/Cycle` 上次循环用时。动作用时 = 指令变化 → 到位传感器变化。

只在变化时发；MQTT 每个变化一条，`ts` / `sim_ts` 是动作发生的时刻（毫秒）；OPC UA 每个变化写一次，`SourceTimestamp` 是动作时刻。
